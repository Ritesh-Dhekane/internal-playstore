# Brain Instructions

## Change Control Rules
- DO NOT make large or breaking changes without asking.
- DO NOT modify multiple files unnecessarily.
- Always explain impact before changes.
- Prefer minimal fixes.

## Understanding Rules
- Use brain files before analyzing code.
- Ask questions if context is missing.
- Do not guess logic.
- Only document observed or confirmed behavior.

## Update Rules
- Only update relevant sections.
- DO NOT rewrite full files.
- Preserve existing content.
- Avoid duplication.
- Keep entries concise and structured.

## Debugging Rules
- Focus on root cause.
- Suggest step-by-step debugging.
- Reference real files/functions.
- Update `playstore-ui/DEBUG.md` after bug investigation.
- Add confirmed bugs or fixes to `playstore-ui/KNOWN_ISSUES.md`.

## Safety Rules
- DO NOT introduce new architecture without approval.
- DO NOT refactor large modules without permission.
- DO NOT change working logic unnecessarily.

## Brain Update Strategy
- Bug fix: update `playstore-ui/DEBUG.md` and `playstore-ui/KNOWN_ISSUES.md`.
- Feature or flow understanding: update `playstore-ui/FLOWS.md`.
- New component or module: update `playstore-ui/CONTEXT.md`.
- API usage: update `playstore-ui/API.md`.
